# webcloner

ابزار خط‌فرمانی (CLI) نوشته‌شده با راست برای کلون کردن یه سایت — تمام صفحات و
فایل‌های فرانت‌اند (CSS، JS، عکس، فونت) — و آماده‌سازی‌ش برای اجرای کاملاً
آفلاین، به سه شکل:

1. یه پوشه/فایل زیپ که می‌تونی مستقیم `index.html`‌ش رو باز کنی
2. یه وب‌سرور محلی
3. یه فایل اجرایی دسکتاپ (با Tauri) که مثل یه اپ واقعی بالا میاد

## نصب و بیلد

روی سیستم خودت (با Rust نصب‌شده — نسخه‌های `Cargo.toml` رو می‌تونی به‌روزتر هم
بذاری، این نسخه‌ها فقط برای سازگاری با محیط تست من پین شده بودن):

```bash
cd webcloner
cargo build --release
# باینری: target/release/webcloner
```

## دستورها

### ۱. دانلود سایت (`download`)

```bash
webcloner download https://example.com --out my-site --zip
```

گزینه‌های مهم:

| گزینه | توضیح | پیش‌فرض |
|---|---|---|
| `--out` | پوشه خروجی | `cloned-site` |
| `--max-pages` | حداکثر تعداد صفحه‌ی HTML برای کرال | ۴۰ |
| `--max-depth` | حداکثر عمق دنبال‌کردن لینک‌ها از صفحه شروع | ۳ |
| `--include-external-assets` | دانلود فایل‌های میزبانی‌شده روی دامنه‌های دیگه (فونت گوگل، CDN و...) | فعال |
| `--follow-external-pages` | دنبال کردن لینک‌های صفحات خارج از دامنه اصلی هم | غیرفعال |
| `--concurrency` | تعداد دانلود همزمان | ۸ |
| `--zip` | بعد از دانلود، یه فایل `.zip` هم بساز | غیرفعال |

خروجی یه پوشه با `index.html` در ریشه‌ست که مستقیم قابل باز کردنه (`file://`)
یا با `webcloner serve` قابل سرو کردنه.

### ۲. سرو کردن محلی (`serve`)

```bash
webcloner serve my-site --port 8787
```

### ۳. زیپ کردن یه پوشه‌ی از قبل دانلودشده (`zip`)

```bash
webcloner zip my-site --out my-site.zip
```

## چطور کار می‌کنه (خلاصه معماری)

1. **کرال صفحات (BFS):** از URL شروع، HTML رو می‌گیره، لینک‌های `<a href>`
   هم‌دامنه رو پیدا می‌کنه و تا `--max-depth`/`--max-pages` ادامه می‌ده.
2. **کشف asset:** برای هر صفحه، تمام `<link>`, `<script>`, `<img>`,
   `srcset`, `<style>` و `style="..."` و فایل‌های CSS جدا رو اسکن می‌کنه —
   داخل خود CSS هم دنبال `url()` و `@import` می‌گرده (برای فونت‌ها و
   بک‌گراندها) و به‌صورت بازگشتی دانلودشون می‌کنه.
3. **بازنویسی رفرنس‌ها:** تمام لینک‌های مطلق رو به مسیر نسبی محلی تبدیل
   می‌کنه (نسبت به فایل خودشون)، طوری که کل پوشه بدون نیاز به اینترنت و حتی
   با `file://` هم کار کنه.
4. **ذخیره:** ساختار پوشه رو تا حد امکان شبیه مسیر URL اصلی می‌سازه؛ فایل‌های
   دامنه‌های دیگه زیر `_external/<host>/...` ذخیره می‌شن.

## محدودیت‌های مهم (صادقانه بگم)

- **سایت‌های کاملاً داینامیک/دارای بک‌اند** (لاگین، فرم ارسال، دیتابیس)
  فقط ظاهر استاتیک‌شون قابل کلون کردنه — منطق سمت سرور قابل آفلاین‌سازی نیست.
- **محتوایی که فقط با اجرای جاوااسکریپت رندر می‌شه** (خیلی از سایت‌های
  React/Vue/Next که سمت کلاینت رندر می‌کنن) ممکنه ناقص دانلود بشه، چون این
  ابزار جاوااسکریپت رو *اجرا* نمی‌کنه، فقط HTML اولیه رو می‌خونه. برای
  پشتیبانی کامل از SPA باید یه مرورگر headless (مثل Playwright/`headless_chrome`)
  اضافه بشه — نسخه فعلی این کار رو نمی‌کنه.
- **محتوای داخل `<noscript>`** پارس نمی‌شه (رفتار استاندارد پارسرهای HTML5
  وقتی جاوااسکریپت "فعال" فرض بشه).
- **فایل‌های JS اسکن نمی‌شن** برای پیدا کردن URL‌های داخلشون (مثلاً
  `fetch('/api/...')`) — چون این کار نیاز به تحلیل کد جاوااسکریپت داره.
- سایت‌هایی که پشت محافظ ربات (Cloudflare و مشابه) هستن ممکنه دانلود رو
  مسدود کنن.

## تبدیل به اپ دسکتاپ آفلاین (پوشه‌ی `desktop-app-template/`)

```bash
# ۱. سایت رو دانلود کن
webcloner download https://example.com --out my-site

# ۲. آیکون بساز (یه‌بار کافیه)
cd desktop-app-template/src-tauri
cargo install tauri-cli --version "^1"
cargo tauri icon /path/to/logo.png
cd ../..

# ۳. بسته‌بندی به اپ دسکتاپ
./desktop-app-template/package.sh ./my-site
```

خروجی زیر `desktop-app-template/src-tauri/target/release/bundle/` یه فایل
اجرایی/نصب‌کننده native می‌سازه (`.exe`+installer روی ویندوز، `.app`/`.dmg`
روی مک، `.deb`/`.AppImage` روی لینوکس) که با اجراش دقیقاً همون سایت رو مثل
یه اپ دسکتاپ نشون می‌ده — بدون نیاز به اینترنت، چون همه‌ی فایل‌ها داخل خود
باینری جاسازی (embed) شدن.

پیش‌نیازهای Tauri (یه‌بار روی سیستمت نصب کن): راهنمای رسمی
https://tauri.app/v1/guides/getting-started/prerequisites

> نکته: پیکربندی `tauri.conf.json` عمداً `allowlist.all: false` و CSP محدود
> داره — یعنی اپ نهایی هیچ دسترسی شبکه/فایل‌سیستم/شل نداره، فقط دقیقاً همون
> فایل‌های استاتیکی که خودت داخل `dist/` گذاشتی رو نشون می‌ده.
